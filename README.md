# И16. Сравнение субъектов по рейтингу

И16 готовит аналитическую справку по выбранным субъектам. Справка показывает опубликованные места и баллы за выбранный период, а при наличии сопоставимого базового периода — динамику по каждому субъекту.

Целевая версия состоит из веб-клиента, сервера с HTTP API и PostgreSQL. Веб-клиент показывает справку, сервер выполняет сравнение, PostgreSQL хранит исходные срезы и результаты рейтинга. Репозиторий содержит проектную документацию и демонстрационный макет.

## С чего начать

Работаем по SDD (Spec-Driven Development). Требования фиксируются в [SPEC.md](SPEC.md), этапы — в [PLAN.md](PLAN.md), задачи с привязкой к проверкам — в [TASKS.md](TASKS.md).

Начните с первой готовой задачи и проверяйте результат по [критериям приёмки](docs/acceptance.md). Для сквозного запуска используйте [демонстрационный набор](examples/demo-dataset.json) и [эталонную справку](examples/demo-brief.md).

## Первый инкремент CLI

Для прототипа предложен локальный CLI на Python 3.11+ со стандартной библиотекой. После реализации команда из корня репозитория будет выглядеть так:

```sh
python3 -m i16 compare \
  --dataset examples/demo-dataset.json \
  --subjects demo-a demo-b demo-c \
  --period 2025 --baseline 2024 \
  --output build/demo-brief.md
```

Задача для Codex на первый инкремент:

> Реализуй T01–T03 из TASKS.md, используя требования и проверки по ссылкам в каждой задаче. Запусти CLI за один период и покажи путь к полученной справке.

## Адаптация для похожего проекта

Опишите аудиторию и вопрос справки, выберите источник и определите единицу наблюдения. Зафиксируйте правила сравнения, подготовьте небольшой вход с известными значениями и запишите ожидаемые выводы. Используйте `SPEC.md`, `PLAN.md`, `TASKS.md`, контракт данных и сценарии приёмки как основу, заменив предметные допущения. Навык можно передать агенту по пути `skills/rating-brief/SKILL.md`.
