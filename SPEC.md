# Спецификация И16

Статус — черновик для прототипа. И16 сравнивает субъекты РФ. Источники и годы для защиты зафиксированы в [сценарии пилота](docs/pilot-ria.md). Требования к рабочей среде уточняются по [плану проекта](PLAN.md).

## Пользовательский сценарий

Аналитик выбирает два или более субъекта и период одного рейтинга, при необходимости задаёт более ранний базовый период. И16 готовит справку, из которой видно, какое место занимает каждый субъект в опубликованном рейтинге, кто лидирует внутри выбранной группы, насколько различаются баллы и что изменилось относительно базы. Источник и ограничения видны в справке.

Основной сценарий пилота проходит в браузере. Веб-клиент получает справочники и результаты по HTTP API. Сервер проверяет параметры, читает данные из PostgreSQL и формирует результат по правилам И16.

Для защиты используется [контрольная выборка РИА Рейтинг](docs/pilot-ria.md) за 2024–2025 годы. Базовое сравнение — ЯНАО и Югра. Тюменская область добавляется в выбор для дополнительного сравнения.

## FR-01. Вход и выход

- Вход CLI и серверного импорта — один JSON-файл по [контракту данных](docs/data-contract.md). В нём есть справочник субъектов и один или несколько срезов одного рейтинга.
- CLI `python3 -m i16 compare` с обязательными аргументами `--dataset`, `--subjects`, `--period`, `--output`. Необязательные аргументы `--baseline` и `--focus-subject` включают динамику и разрывы по опорному субъекту соответственно. Годы задаются явно.
- Один файл Markdown в UTF-8 по [шаблону справки](docs/brief-template.md). Текст строится из вычисленных значений и повторяемых формулировок. Одинаковые данные и параметры сравнения дают одинаковый текст, включая порядок строк и выводов.

## FR-02. Сравнение за период

1. Берите места из выбранного среза. Сохраняйте опубликованный номер места при любом наборе выбранных субъектов. Общее число субъектов рейтинга берите из метаданных среза.
2. Показывайте выбранные субъекты по возрастанию места. При равном или отсутствующем месте используйте идентификатор для стабильного порядка. Субъекты без места идут после субъектов с местом.
3. Определяйте лидеров выбранной группы по минимальному месту. При ничьей перечисляйте всех лидеров. Если места доступны лишь части группы, формулируйте результат как наивысшую из доступных позиций. Для этого вывода нужны как минимум два известных места.
4. Разброс баллов равен `максимум − минимум` по доступным баллам выбранной группы. Показывайте его при наличии хотя бы двух баллов. При неполном покрытии указывайте число доступных значений и размер группы.
5. Сохраняйте в таблице строку выбранного субъекта, даже если в срезе её поля отсутствуют. Показывайте пропуск как `—`, а результат помечайте как частичный при пропуске любого запрошенного значения. Нулевой балл сохраняйте как значение.

## FR-03. Динамика

Базовый период указывается явно и должен предшествовать выбранному. Без базы справка показывает сравнение за один период.

| Показатель | Условия | Формула и интерпретация |
| --- | --- | --- |
| Балл | Одинаковая версия методики, одинаковые границы шкалы, оба значения известны | `балл текущий − балл базовый`. Плюс означает рост балла. |
| Место | Те же версия методики и шкала, подтверждённый одинаковый `cohort_id`, одинаковая численность рейтинга, оба места известны | `место базовое − место текущее`. Плюс означает улучшение позиции. |

Если версия методики или границы шкалы различаются, покажите опубликованные значения обоих периодов, отметьте причину и опустите обе дельты. Если отличается охват или его сопоставимость не подтверждена, опустите дельту места. Изменение балла остаётся доступным при выполнении условий для балла. Пропуск исходного значения влияет только на связанную дельту. Любая недоступная дельта делает справку частичной. Изменения места и балла описывайте отдельно. Причинные выводы требуют дополнительных данных и выходят за рамки прототипа.

## FR-04. Ошибки и сохранение

- Отклоняйте некорректный JSON, нарушение контракта, неизвестные или повторные ID в запросе, выбор менее двух субъектов и ненайденный период. Отсутствие всех текущих мест и баллов в выбранной группе — ошибка. При одном доступном значении формируйте частичную справку.
- При ошибке ввода выводите понятное сообщение в `stderr` и возвращайте код `2`. При ошибке чтения или записи возвращайте код `1`. Успешный результат, включая частичную справку, возвращает `0`.
- По указанному пути можно сохранить новый результат или заменить прежнюю справку целиком. При записи создавайте родительский каталог по необходимости. При ошибке существующая справка должна сохраниться, а новый файл — отсутствовать. Входной файл должен оставаться доступным и неизменным. Если пути ввода и вывода указывают на один файл, отклоните запрос с кодом `2`.

## FR-05. Визуальное оформление

Для экранной и печатной версии справки используйте [визуальный стиль И16](docs/visual-style.md) на основе мастер-бренда «Ямал». Применяйте фирменную палитру и крупные заголовки, сохраняя читаемость таблицы, источников и дельт на широком экране, на телефоне и в печати. Значения и порядок строк должны совпадать со справкой на тех же данных. [HTML-макет](examples/rating-preview.html) задаёт визуальный ориентир для пилота.

## FR-06. PostgreSQL и загрузка данных

PostgreSQL хранит рейтинг, справочник субъектов, годовые срезы с источниками и опубликованные результаты. Схема разворачивается миграциями. Серверный импорт принимает JSON по FR-01, проверяет весь набор и загружает его одной транзакцией. Повторная загрузка того же файла даёт то же состояние данных. Баллы сохраняются с десятичной точностью, пропуски — как SQL `NULL`.

## FR-07. Сервер и HTTP API

Сервер отдаёт доступные периоды и субъектов, принимает запрос на сравнение, читает связанные данные из PostgreSQL и возвращает структурированный результат. Сервер и CLI вызывают единый модуль сравнения по FR-02 и FR-03. Ошибки параметров и недоступность данных возвращаются с объяснением. Точки входа описаны в [архитектуре](docs/architecture.md).

## FR-08. Веб-клиент

В браузере аналитик выбирает текущий период, при необходимости более ранний базовый период и минимум два субъекта. Из них можно выбрать опорный субъект по FR-09. Клиент запрашивает сравнение у сервера и показывает краткий итог, таблицу, источники и ограничения. Предусмотрено отдельное действие для формирования справки с ИИ по FR-10. Для частичной справки сохраняются доступные значения. Интерфейс показывает загрузку и ошибки. Оформление соответствует FR-05.

## FR-09. Разрывы по баллам

Аналитик может указать один опорный субъект из выбранных. Для каждого другого выбранного субъекта сервер рассчитывает `балл опорного − балл сравниваемого` отдельно за каждый показанный период. Положительное число означает преимущество опорного субъекта, отрицательное — отставание, ноль — равенство баллов. Субъекты вне выбора в этот блок не попадают. Без опорного субъекта блок отсутствует. Опорный субъект вне выбора — ошибка параметров.

Если известны оба разрыва и баллы сопоставимы по FR-03, покажите изменение `текущий разрыв − базовый разрыв`. При несопоставимости можно показать оба разрыва за отдельные годы с пояснением. Если в периоде не хватает хотя бы одного балла, соответствующий разрыв и его изменение недоступны.

## FR-10. Справка с помощью ИИ

По отдельному запросу аналитика сервер передаёт модели рассчитанные факты с идентификаторами и допустимыми формулировками. Модель выбирает и упорядочивает утверждения для краткого итога. Сервер проверяет выбор и подставляет значения из расчёта. Таблица, даты, источники, ограничения и обязательные для интерпретации факты сохраняются при обоих способах формирования справки.

При недоступности модели, неверном формате или ссылках на неподтверждённые факты сервер возвращает детерминированную справку и сообщает, какой способ использован. Причины изменения рейтинга требуют отдельной доказательной базы и в пилотную справку не включаются.

## Состав первой версии

В MVP входят веб-клиент, сервер, PostgreSQL, импорт выгрузки одного рейтинга, сравнение с необязательной базой и формирование справки. На защите предусмотрен сценарий с ИИ по FR-10. Первый технический инкремент проверяет расчёты через локальный Python CLI и формирует детерминированную Markdown-справку. Правила доступа и конфигурация модели уточняются по [плану](PLAN.md).
