# План проекта И16

Цель первой версии — дать аналитику веб-клиент для сравнения субъектов и просмотра справки. Сервер выполняет расчёты на данных из PostgreSQL. Первый проверяемый результат — справка за один период по трём демосубъектам через CLI.

Результаты этапов следуют из [спецификации](SPEC.md). Порядок реализации, зависимости и проверки каждой работы приведены в [TASKS.md](TASKS.md).

## Этапы

| Этап | Что сделать | Результат и проверка | Зависимость |
| --- | --- | --- | --- |
| 0. Уточнить постановку | Проверить источники, подготовить [выборку РИА Рейтинг](docs/pilot-ria.md) и сверить решения для пилота. | Зафиксированы публикации, отчётные годы, состав и контрольные числа. | Среду и доступ подтвердить к этапу 4. Этапы 1–3 можно выполнять на демоданных. |
| 1. Собрать сквозной сценарий | Реализовать чтение и валидацию JSON, выбор субъектов и периода, сравнение мест и баллов, вывод Markdown через CLI. | Запуск без `--baseline` на демоданных даёт справку с опубликованными местами `2, 2, 4`, двумя лидерами среди выбранных и диапазоном `4,50` балла. Проходят A01, A02, A06, A07, A10, A11. | [Контракт данных](docs/data-contract.md) и [шаблон справки](docs/brief-template.md). |
| 2. Добавить динамику | Добавить базовый период, правила сопоставимости, обработку пропусков и разрывы по опорному субъекту. | Запуск с `--baseline 2024` воспроизводит [эталонную справку](examples/demo-brief.md). Проходят A01–A11, A18 и A19. | Этап 1. |
| 3. Собрать веб-версию | Подготовить миграции и импорт PostgreSQL, связать API с расчётом, собрать клиент и дашборд по [стилю И16](docs/visual-style.md), добавить формирование итога с ИИ и воспроизводимый прогон сквозных проверок. | Сравнение из браузера воспроизводит эталон, графики согласованы с таблицами, изменение параметров помечает предыдущую справку. Приёмка по A12–A16, A20–A26 и V01–V04. | Этап 2 и [архитектура](docs/architecture.md). |
| 4. Провести пилот | Импортировать данные РИА в PostgreSQL, проверить полный список ранжированных регионов, подготовить экран, карту и справку для руководителя, пройти [сценарий защиты](docs/pilot-ria.md). | Точные числа, публикации и даты видны в веб-справке. Расширенный справочник, справка A4 с фото региона и карта проходят A27–A31. Пилот принят читателем по A17. | Этапы 0 и 3. |
| 5. Обновлять и использовать данные | Подключить расписание проверки сводной таблицы РИА, аналитику и импорт источников в панели администратора, MCP-сервер. | Проверены загрузка, журнал, сверка покрытия, защищённые операции и вызовы MCP через `stdio`. A32–A36. | Этапы 3 и 4. |
| 6. Открыть самостоятельный доступ | Добавить подтверждение email через SMTP, сессии PostgreSQL и рабочую область с каталогом рейтингов. | Проверены вход по письму, выбор рейтинга, сравнение и выход. A37. | Этап 5. |
| 7. Помочь ориентироваться в интерфейсе | Добавить помощника с LLM-ответами по справочнику разделов, переходами и резервными подсказками. | Проверены ответы модели, отказ провайдера, переходы и отображение на узком экране. A38–A39. | Этапы 5 и 6. Для живой проверки нужна настроенная модель. |
| 8. Настроить оформление | Добавить системную, светлую и тёмную темы и «Северное сияние». | Проверены переключение, сохранение выбора, карта, помощник и печать. A40. | Этапы 3, 6 и 7. |
| 9. Сопоставить открытые показатели | Подключить опубликованные ряды по рождаемости, топливу и ИИ, добавить ссылки на карты связи. | Покрытие, периоды и пропуски видны в сравнении. Сопоставление проходит A41. | Этап 4 и [каталог источников](docs/public-data-sources.md). |
| 10. Принимать обратную связь | Добавить форму на странице рейтинга и входящие в панели администратора. | Отправка, повтор при ошибке и чтение после входа проходят A42. | Этапы 3 и 5. |
| 11. Собрать итоговую справку | Разместить показатели на вкладках, собрать их в одном документе и добавить возврат к началу страницы. | Проверены переключение, пересчёт, источники, сохранение в PDF и возврат наверх. A43–A44. | Этапы 4 и 9. |

Проверки описаны в [критериях приёмки](docs/acceptance.md). Порядок реализации этапа 1 — загрузка данных, расчёт, формирование текста и вызов через CLI. Критерий готовности веб-версии — успешный сквозной запуск на демоданных через браузер, API и PostgreSQL. Критерий готовности к рабочему использованию — принятый пилот.

## Решения для пилота

| Что подтвердить | Рабочее допущение для прототипа | Что зафиксировать перед пилотом |
| --- | --- | --- |
| Рейтинг и список субъектов | Серия РИА Рейтинг. На защите сравниваются ЯНАО, Югра и Тюменская область | Состав рабочей выборки после защиты |
| Источник выгрузки | Локальный JSON по проектному контракту. Точные числа и публикации редакции указаны в [материалах пилота](docs/pilot-ria.md) | Порядок обновления при выходе новых выпусков |
| Периоды и совокупность | 2025 год, база 2024, по 85 опубликованных мест | Сопоставимость будущих выпусков |
| Правила рейтинга | Места из публикации, больший балл означает более высокую оценку | Направление и точность шкалы, ничьи, опубликованные места, сопоставимость методик |
| Аудитория и результат | Аналитик, справка в веб-клиенте, Markdown для локальной проверки | Получатель, обязательные разделы, требуемый формат передачи |
| Среда пилота | Локальный веб-клиент, сервер и PostgreSQL | Где размещаются компоненты и кто имеет доступ |
| Справка с ИИ | Модель выбирает формулировки из рассчитанных фактов, сервер поддерживает шаблон | Доступная в среде пилота модель и настройки доступа |

Если выгрузка расходится с рабочими допущениями, обновите спецификацию, контракт и сценарии приёмки одним изменением.

## Предложения для следующей итерации

Перед внешним пилотом проверьте доставку ссылки в рабочий почтовый ящик, вход через HTTPS и показ справки читателю по A17. В автопроверке письма попадают в тестовый ящик, а генерация проверена через локальный Ollama.

| Приоритет | Предложение | Как проверить результат |
| --- | --- | --- |
| 1 | Сохранять сравнения в рабочей области и копировать ссылку с параметрами. | Аналитик повторно открывает тот же рейтинг, периоды, набор субъектов и опору. Ссылка воспроизводит параметры, а для фиксации самих чисел указывается версия среза. |
| 2 | Добавить выбор рейтинга в админ-аналитике, предварительный просмотр импорта и версии срезов. | Администратор проверяет покрытие любого рейтинга и видит конфликты до записи. После загрузки можно установить источник и время записи, сравнить версии и восстановить нужный срез. |
| 3 | Выгружать таблицу сравнения в CSV. | Файл содержит показанные строки, места, баллы, дельты, периоды и ссылки на источники. Пропуски сохраняются. |
| 4 | Запускать базовый E2E в CI и показывать состояние сервиса. | Сквозные проверки выполняются для изменений репозитория. Оператор видит доступность базы и время последней успешной загрузки. |
| 5 | Расширить региональную статистику безработицей и ВРП на душу населения. | Показатели отображаются с единицей, годом, охватом и ссылкой на выпуск. |
