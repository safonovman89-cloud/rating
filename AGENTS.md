# Работа над И16

- Работай по SDD. Найди задачу в [TASKS.md](TASKS.md), прочитай связанное требование [SPEC.md](SPEC.md), этап [PLAN.md](PLAN.md) и её [критерии приёмки](docs/acceptance.md). Для полей и формата входа используй [контракт данных](docs/data-contract.md).
- При изменении поведения сначала обнови требование и затронутые сценарии приёмки, затем план и задачу, если изменились зависимости или результат этапа. Считай задачу выполненной после проверки её наблюдаемого результата.
- Для подготовки и ревью справок используй [навык rating-brief](skills/rating-brief/SKILL.md). Для одного изменения читай только относящиеся к нему материалы.
- Держи загрузку и валидацию данных, расчёты, формирование Markdown и CLI раздельно. Рассчитывай сравнения один раз и передавай готовый результат в шаблон. Используй точную десятичную арифметику для баллов.
- При работе над веб-версией сверяйся с [архитектурой](docs/architecture.md). Сервер и CLI вызывают единый модуль сравнения. Веб-клиент отображает ответ API, а изменения схемы PostgreSQL оформляются миграциями.
- Применяй опубликованные места и стабильные ID. Явно сохраняй пропуски, область рейтинга и правила базового сравнения. Перед изменением формулы обнови спецификацию и затронутые сценарии приёмки.
- Для проверки защиты используй [выборку РИА Рейтинг](docs/pilot-ria.md). Разрывы вычисляй на сервере из баллов выбранных субъектов. В режиме ИИ подставляй только проверенные факты и возвращай шаблон при сбое модели.
- Проверяй изменение через `python3 -m i16 compare` после появления CLI. Для расчётов сверяй строки справки с демонабором. Для веток с ошибками проверяй код завершения и состояние файла результата.
- Включай в репозиторий только демонстрационные наборы или данные, явно разрешённые для хранения в нём. В готовой справке указывай доступный читателю источник и период.
- Для визуального оформления рейтинга и справки используй [графические правила И16](docs/visual-style.md) и сверяй вывод с [макетом](examples/rating-preview.html).
